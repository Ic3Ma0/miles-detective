# 社交平台正文按登录态取回，批量采集只用于公开内容

知乎、小红书等平台已把问答和笔记整体移到登录墙后，搜索摘要成了唯一可见材料；只用搜索会把“登录墙”误记成“平台没有内容”，也会把导航壳当成读过。我们决定把平台正文取回分成三层：公开接口优先（微博移动版、B 站公开 API）；登录墙用一次性人工登录的持久浏览器 profile（`scripts/social_fetch.py`）；需要批量或评论时用 MediaCrawler（`scripts/mediacrawler.py`，经 CDP 复用已登录 Chrome）。取回结果统一转成 `visit` + `source` 记录（`scripts/mc_to_records.py`）；未取回的访问记 `shell` 或 `unretrieved`，不写成 `content`。

选择依据：登录墙不是反爬失败，而是平台把内容放进账号体系，绕过它既不合规也不稳定；复用本人已登录的浏览器是唯一同时满足“可维护”和“不绕过访问控制”的方式。批量采集只覆盖中文平台、不含 X，且 MediaCrawler 是非商用学习许可，因此只在个人研究中使用，不进入默认流程；X 走登录态浏览器。代价是账号风控、频率限制和平台改版：脚本先自检登录态与 CDP 端口，失败时按访问台账记录具体层级，不静默重试，也不把失败写成平台封禁。
