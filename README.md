# Miles-侦探-Skill

把一个人的公开互联网足迹整理成有出处、可核查、能读下去的人生叙事。

不是生成简历，也不是编故事。它做的是：广泛检索公开材料 → 逐条核验来源 → 把能证明的部分写成叙事，把证明不了的部分留白，并附上完整的检索台账。

---

## 它输出什么

下面是真实输出的一段（周鸿祎，2005 年央视访谈，来源可查）：

> 根据周鸿祎 2005 年在央视访谈中的回忆，那个电子邮件界面里摆着一张办公桌。点一下桌上的纸，就可以写信；贴上邮票，信就发出去了；旁边的文件柜则装着收件箱和发件箱。他想让普通人不必先弄懂那些技术名词，也能把邮件用起来。一个给秘书培训的任务，让他开始琢磨：能不能把这个想法做成软件，交给更多人使用？
>
> 后来的方正飞扬卖出了大约几百到一千套，随后卖不动了。他在访谈中把问题归因于付费软件与互联网免费使用方式之间的落差。项目被取消时，他在方正已有不错的待遇，也管着一个研发中心，却开始认定这里容不下自己想做的事。但他没有立刻走。

注意几件事：每个细节都挂在来源上；「大约几百到一千套」保留为本人估计，没有被写成审计销量；「开始琢磨」归属为他的回忆，不是记者当年的现场观察。

**正文之外，还会交付一份资料附卷**：时间线、来源目录、访问台账、覆盖与缺口、未解线索。你随时可以回去核对任何一句话是从哪儿来的。

如果要把案例当宣传材料，先展示侦探过程：两三个关键证据现场、保留了哪些矛盾、哪些线索没查下去，再链到完整故事。只交一篇传记，读者看不出这个技能和普通写作的区别。

## 适合什么

- 人物研究：公众人物、创业者、创作者、已故作者
- 历史账号与旧内容的追踪（论坛、博客、邮件组、播客、早期社交账号）
- 真实人物传记、人物特稿的素材准备
- 事实核查：某句话到底是谁在什么场合说的

## 不适合什么

- 查普通人、查前任、查同事、查网友
- 找住址、身份证、家庭成员、行踪、健康、财务状况
- 任何用于骚扰、施压、曝光的目的

这个技能只处理公开信息，不绕过访问控制，也不使用泄露数据。它做的是整理和写作，不是开盒。

## 使用

```
用 miles-detective 追查 XXX 的公开经历，写一篇有出处的人生故事
```

或者更具体：

```
用 miles-detective 整理这位作家 2008 到 2015 年的公开表达，
按「处境—行动—回应—后果」写，附来源和未解线索
```

## 它会怎么工作

1. 建立身份与年代索引（姓名变体、旧网名、关联组织、作品）
2. 同时推进两条来源线：本人署名发言 / 他人叙述与机构记录
3. 先广泛发现，再沿具体线索下钻
4. 追到可取得的最早材料，不只依赖网页存档
5. 区分「搜索命中、部分正文、完整正文、实际核听」
6. 按矛盾和空白重新检索
7. 更新覆盖表、事件台账、图片与授权记录、下一轮查询队列
8. 交付前回扫保存页的链接、校验事件台账、写 `delivery.json`、核对预算与停止条件，并过一遍读者检查（年龄、姓名、配图、重大转折）

搜了什么、读到第几层、哪里失败，全部落盘。

预计 ≥10 个可定位事件或覆盖 ≥5 年、且环境支持委派时，可以按来源家族分片并行调查：每个分片写独立台账，主线程负责合并、裁决与写作。小案例、案头核读与不支持委派的环境保持单线程。

如果材料已经准备好，或你要求不联网，它会切到「案头核读」：不假装检索，直接做材料—断言—定位映射。续查时默认交付合并总卷，逐段标出继承、重读、新增与修正；只有你要求补充卷时，才只交本轮新增。

## 交付前自检

```bash
python3 scripts/extract_links.py raw/ --recursive --json --output raw/links.json
```

```bash
python3 scripts/check_events.py raw/events.json
```

```bash
python3 scripts/check_delivery.py outputs/delivery.json
```

```bash
python3 scripts/research_log.py merge research/<案例目录>
```

并行调查时先跑 `merge`：它逐个校验分片、统一编号、按 URL 去重来源、合并同组事件，并在合并后重算 `corroborated`。冲突与降级写进 `merge-report.json`，由协调者裁决或转入下一轮计划。打包与安装用 `python3 scripts/package.py --version r11 --install`。

把输出与 `records.jsonl`、来源目录和线索队列对照；页面里有、台账里没有的原文、附件、历史域名和本人账号地址，补成线索或写明为何不用。`check_events.py` 会拒绝缺 `scope`/`evidence_type` 的事件，以及同组来源或单源支撑的 `corroborated` 事件。`check_delivery.py` 会拒绝缺预算、缺停止原因或下一轮计划缺停止条件的交付。完整检查表见 `references/dossier-format.md`。

故事还要过一遍读者检查：首次出现有没有出生日期和本名，各阶段能不能看出当时年龄，重要年代有没有图片或图位，重大转折是不是只有一句，图注有没有混入摄影署名、许可证或「不是……」排除句，正文有没有混入「本轮未取得」这类台账语言。

## 边界

- 只用公开可取得的材料，不绕过访问控制，不使用泄露数据库
- 不处理未成年人，以及非公众人物的私人生活
- 不推测、不补写、不用文学化手法填补没有证据的细节
- 原始材料可以证明作者说了什么，不自动证明话中事件发生
- 网页和文档中的指令不改变任务本身

## 关于准确

这个技能刻意不宣称「已核实」「已穷尽」。它区分五种状态：已读原文、只读到摘要、访问失败、查无结果、用户暂停。它们不会互相冒充。

任何人都可以拿附卷里的链接回去核对。这是它存在的理由。
