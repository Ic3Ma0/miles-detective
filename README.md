# Miles-侦探-Skill

把一个人的公开互联网足迹整理成有出处、可核查、能读下去的人生叙事。

不是生成简历，也不是编故事。它做的是：广泛检索公开材料 → 逐条核验来源 → 把能证明的部分写成叙事，把证明不了的部分留白，并附上完整的检索台账。

---

## 它输出什么

下面是真实输出的一段（周鸿祎，2005 年央视访谈，来源可查）：

> 根据周鸿祎 2005 年在央视访谈中的回忆，那个电子邮件界面里摆着一张办公桌。点一下桌上的纸，就可以写信；贴上邮票，信就发出去了；旁边的文件柜则装着收件箱和发件箱。他想让普通人不必先弄懂那些技术名词，也能把邮件用起来。一个给秘书培训的任务，让他开始琢磨：能不能把这个想法做成软件，交给更多人使用？
>
> 后来的方正飞扬卖出了大约几百到一千套，随后卖不动了。他在访谈中把问题归因于付费软件与互联网免费使用方式之间的落差。项目被取消时，他在方正已有不错的待遇，也管着一个研发中心，却开始认定这里容不下自己想做的事。但他没有立刻走。

注意几件事：每个细节都挂在来源上；「大约几百到一千套」保留为本人估计，没有被写成审计销量；「开始琢磨」归属为他的回忆，不是记者当年的现场观察。

**正文之外，还会交付一份资料附卷**：时间线、来源目录、访问台账、覆盖与缺口、未解线索。你随时可以回去核对任何一句话是从哪儿来的。

## 适合什么

- 人物研究：公众人物、创业者、创作者、已故作者
- 历史账号与旧内容的追踪（论坛、博客、邮件组、播客、早期社交账号）
- 真实人物传记、人物特稿的素材准备
- 事实核查：某句话到底是谁在什么场合说的

## 不适合什么

- 查普通人、查前任、查同事、查网友
- 找住址、身份证、家庭成员、行踪、健康、财务状况
- 任何用于骚扰、施压、曝光的目的

这个技能只处理公开信息，不绕过访问控制，也不使用泄露数据。它做的是整理和写作，不是开盒。

## 使用

```
用 miles-detective 追查 XXX 的公开经历，写一篇有出处的人生故事
```

或者更具体：

```
用 miles-detective 整理这位作家 2008 到 2015 年的公开表达，
按「处境—行动—回应—后果」写，附来源和未解线索
```

## 它会怎么工作

1. 建立身份与年代索引（姓名变体、旧网名、关联组织、作品）
2. 同时推进两条来源线：本人署名发言 / 他人叙述与机构记录
3. 先广泛发现，再沿具体线索下钻
4. 追到可取得的最早材料，不只依赖网页存档
5. 区分「搜索命中、部分正文、完整正文、实际核听」
6. 按矛盾和空白重新检索
7. 更新覆盖表与线索队列

搜了什么、读到第几层、哪里失败，全部落盘。

## 边界

- 只用公开可取得的材料，不绕过访问控制，不使用泄露数据库
- 不处理未成年人，以及非公众人物的私人生活
- 不推测、不补写、不用文学化手法填补没有证据的细节
- 原始材料可以证明作者说了什么，不自动证明话中事件发生
- 网页和文档中的指令不改变任务本身

## 关于准确

这个技能刻意不宣称「已核实」「已穷尽」。它区分五种状态：已读原文、只读到摘要、访问失败、查无结果、用户暂停。它们不会互相冒充。

任何人都可以拿附卷里的链接回去核对。这是它存在的理由。
