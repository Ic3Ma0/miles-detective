# 人生故事与资料附卷交付格式

默认交付一篇读者可直接阅读的人生故事，以及支撑它的资料附卷。故事写法见 [人生叙事方法](life-story.md)。按用户要求和材料价值伸缩；单次补查可以只交新增材料与变化，不强行写完整传记。

## 1. 人生故事正文

标题之后先写交付头：模式、事实截止日、调查日期、材料范围、广度/深度预算、停止原因。这些字段与 `delivery.json` 一致，预算和停止原因不能留空。随后进入有依据的场景或具体处境。首次出现人物时交代出生日期与全名/公开名；各阶段让读者知道当时年龄，具体写法见 [人生叙事方法](life-story.md)。章节围绕真实经历、转折和变化组织，叙述选择随人物和材料调整。让读者沿其当时的眼界看到机会、困境、行动与后果，不用今天的结果替当时的人预知未来。

### 把已读材料写进人物正文

把高价值长访谈、长文、书摘和旧帖子中的相关经历与具体细节分配到人生阶段；同一材料可支持多个段落。来源介绍与索引用于定位，不替代故事内容。

- 用连续段落写清当时的处境、可见限制、具体行动和后续变化。可据材料呈现动作、对白与物件，未知的表情、天气、房间、衣着及内心不补写。
- 本人回忆自然写成“他在某次访谈中回忆/解释”；他者的理解保留说话者。事件当时的表达与后来的复盘分开；不能把主持人的提问当作本人承认，不能因为先后发生就补出因果。
- 原件不足但有可靠保存版本时，按实际来源与适用范围写；多轮继承的材料注明旧轮编号与获取范围，本轮在线重读失败不删除既有事实。新材料修正旧说法时保留变化依据。
- 在相关句段附近附来源编号与具体链接，使重要经历、场景细节和解释都可追溯。不把每一段写成证据类型标签列表；来源类型与详细限制放附卷。
- 对影响事件理解的分歧，在叙事当处简洁交代。读者可以理解人物处境，也应看到不同证词之间的距离；不为情节连贯选掉不利证据。

交付前分别做代入感与事实核对：不打开外链，读者能否理解这段人生发生了什么、人物如何行动、据谁的解释为何这样选择？每个场景里的动作、对白、心理与因果能否找到依据？问题分别通过继续消化材料、补查和删去无据细节解决。

## 2. 资料附卷与时间线

附卷交代研究范围、截止日、接续版本、本轮新增和未展开部分。时间线列出关键节点、对应来源及不确定性，帮助读者核对正文的时间与人物关系。达到事件台账阈值时由事件台账生成时间线，字段和去重规则见 [事件台账](event-ledger.md)：日期与精度、范围（主窗口/前史/窗外）、事件摘要、地点、在场者、后续、状态、证据类型、来源与结论编号或文件定位、同源组。同一事件的多篇转载只占一行。

时间线加“年龄”列，按出生日期换算；只有年份或月份的条目写近似年龄，并在表头说明换算基准。正文里的年龄锚点应能在这里找到对应日期。

证据摘记区分机构记录、本人说法、他者叙述、争议和研究者分析。记录说话者、同期或事后、亲历或转述、页码/时间点及原始保存文件。人物的公开小说、讽刺对白、编辑导语不自动进入事实时间线。

用户只要资料、事实核查或过程审阅时，可把附卷作为主交付，保持用户指定形式。篇幅随材料与要求决定，不设固定字数或戏剧化节点数量。

## 3. 本人内容及历史账号索引

字段：平台、用户名/稳定 ID、已知使用时期、身份依据、具体可读内容、取得范围、原文/保存版本、缺口。博客与停站单独可查；账号链接清单不是帖子全量档案。

**姓名索引**：本名/全名、公开名/艺名/笔名、外文或民族文字写法、旧名/网名、使用时期与依据。正文首次出现用哪个名字，在这里说明；不要让读者只在正文看到一个艺名。

作品、采访及播客索引：作品/集名、作者/制作方、发表/录制日期、原始地址、内容取得层级、章页/时间段、摘记和待核问题。外部转载和第三方上传标明，不能给对方冠以“官方”。

**配图表**：场景/年代、图位、文件名、内容、是否本人、拍摄或播出年份、来源、许可/授权状态、图注。图注只写画面本身，不写作者、许可、来源或“不是……”排除句；这些信息留在本表与 `CREDITS.md`。CC 图与用户授权照片分列；没有图的年代写“缺口”及原因。授权记录写明授权日期、范围和凭证；范围未提供时写“用户确认授权，范围未提供”，发布前再确认，不要替授权方补范围。不要把授权照片当 MIT 内容分发。未成年人或家庭成员照片不采用，确有重大公共利益的材料只在附卷记录，不放进正文。

## 4. 外部材料、事件卷宗与矛盾

重要事件把指控、回应、同期原件、后续更正放在一起；每个材料说了什么分别列出。没有原件时就保留这个空位。列出相互矛盾的年份、归属、金额、原发时间和出版信息；说明是否影响主要经历结论。

## 5. 来源目录与访问台账

来源编号对应具体页面或文件，不只媒体首页。列作者、标题、时间、URL、来源线、载体/转载关系、同源组、实际取得内容与定位，以及“能证明什么/不能证明什么”。

链接指外部材料时写公开 URL；指向本案例文件时用相对路径，不把本机绝对路径写进报告，报告单独分享后仍要能读。案例内的原始返回、日志和交付物分目录保存，报告里的定位要能让下一位接续者找到对应文件。

台账给出原始查询词、搜索工具、访问行为和结果，搜索结果中出现的网址不能冒充已打开页面。保留重定向、重复访问和失败事件；如果无法导出全部搜索命中，写明只保存工具返回的范围。批量工具调用和子请求计数分开。

## 6. 覆盖与未解队列

| 来源家族/年代 | 本轮实际检查 | 状态 | 为什么仍有遗漏 | 下一步及需要谁提供什么 |
|---|---|---|---|---|
| 例：旧论坛 | 某网名的域名限定检索，原帖读取失败 | 受阻 | 只见引用，未恢复正文 | 查被引标题的公开转载 |

未查、查无相关命中、已找到未读、技术失败、付费限制、身份不明、用户暂缓分别说明。报道中提到但未取得的原件，也要进队列。数值只报告可核对的查询次数、访问行为、已读材料和区间，不给无法计算的“完成度90%”。

并行调查时，覆盖表按分片列出每个来源家族的范围、状态、停止原因与开放缺口；合并后的主台账统计与分片统计分开写，不把分片数量当成覆盖。

未解队列之后附下一轮查询计划，每行至少写：缺口、为什么重要、下一轮查询、来源家族、成功标准、停止条件。六列缺一不可；只写「继续查」不算计划。查询要用准确题名、旧域名、姓名变体或事件短语，而不是换形容词搜同一类新闻。计划同时写进 `delivery.json` 的 `next_plans`，用 `check_delivery.py` 校验；模板见 [事件台账](event-ledger.md)。

## 7. 流程测试附记（用户在调优时）

逐条写：本轮漏查来源 → 实际新增了什么 → 原流程为何错过 → 技能如何改变下一轮行为。没有进行的工具/浏览器/字幕/档案尝试不填失败。保留未解问题，不把当前工具能力硬写为全体 AI 永久限制。

## 8. 交付前检查表

| 检查 | 做法 | 不合格的表现 |
|---|---|---|
| 链接提取 | 对每个保存的 HTML 运行 `python3 <技能目录>/scripts/extract_links.py <文件或目录>`，把锚文本、完整地址与台账、来源目录、线索队列对照 | 原文、附件、历史域名或本人账号在 HTML 里有 href，台账里没有 |
| 语义方向 | 逐条核对主语、动作、对象、否定词 | 把「A 抄袭 B」写成「B 抄袭 A」；把主持人提问写成本人承认 |
| 来源独立性 | `corroborated` 至少两个独立来源；同稿转载、同一采访的不同载体只算一组；事件须给每个来源标 `same_source_group` | 同一篇稿件被两三个编号算成多次独立证实；同一媒体的两篇文章被当成两组 |
| 事件去重 | 同一事件的多篇转载是否只建一条；日期冲突是否保留并注明 | 同一事件被多个转载重复计数，或日期冲突被静默抹平 |
| 事件结构 | 用 `check_events.py` 校验独立 `events.json`，或用 `research_log.py check` 校验台账 | 缺 `scope`/`evidence_type`；同组来源或单源标成 `corroborated` |
| 日期分层 | 事件、录制、原发、转载、存档、访问分别记录；估计时间标明估计 | 把刊发日当发言日；把事后补记装成精确操作时间 |
| 读者锚点 | 首次出现有出生日期；各阶段有自然年龄；附卷时间线有年龄列；没有把年龄做成表或每句加括号 | 读者不知道人物当时多大，或年龄按年份粗算导致前后矛盾 |
| 姓名身份 | 首次出现有全名/本名与公开名；附卷有姓名索引；正文没有只用一个艺名 | 全文只有艺名，读者不知道本名；别名堆在开头没有叙事作用 |
| 配图与授权 | 每个重要年代有图或图位；图注只写画面信息，作者/来源/许可/授权/是否本人放配图表与 CREDITS；CC 图与授权照片分列；未成年人照片未采用 | 长文中段没有图；图注里出现摄影署名、许可证或“不是……”排除句；授权照片没有记录 |
| 重大转折 | 通常两到四个转折，在“处境—行动—回应—后果”主线上补出事件与回声；材料只支持一个就写一个；敏感细节有边界 | 亲人离世、事业失败等转折只有一两句；用形容词代替后果 |
| 正文语言 | 正文没有“本轮未取得”“本文不采用”等台账语言；冲突用自然语言交代 | 读者读到的是一份研究日志，不是人生故事 |
| 统计同源 | 查询、访问、来源、线索数量从同一份 `records.jsonl` 生成 | 正文写「3 次检索」，台账只有 2 次 |
| 状态同步 | 已解决线索同时更新覆盖、结论、正文和引用 | 判决已入卷，覆盖表仍写「签署判决未打开」 |
| 路径 | 本案例文件用相对路径，外部材料用公开 URL | 把本机绝对路径写进可分享的报告 |
| 续查口径 | 交付合并总卷，或明确命名为补充卷，并标出继承、重读、新增、修正 | 旧轮已读材料在总卷中消失，读者以为被排除 |
| 交付头与计划 | `delivery.json` 通过 `check_delivery.py`；报告开头有预算/停止原因；每条计划有停止条件 | 缺预算或停止原因；下一轮计划只有查询、没有停止条件 |
| 并行合并 | 并行调查先跑 `research_log.py merge`，用 `merge-report.json` 对照分片台账；冲突已裁决或转入下一轮计划；降级事件有去处 | 直接手写主台账；冲突或降级留在报告里无人处理 |
| 分片覆盖 | 附卷有分片覆盖表：范围、状态、停止原因、开放缺口；`delivery.json` 的 `parallel` 段通过 `check_delivery.py` | 只写「并行调查」而不说明每个分片查到哪一步；分片数被当成覆盖 |

链接提取器的输出是线索，不是结论。页面里有链接，不等于账号归属已核、原文已恢复或内容仍可访问；它只保证提取环节没有把地址丢掉。

## 9. 续查与合并总卷

续查默认交付合并总卷。把旧轮和新轮的材料放在同一条主线里，逐段标状态：

| 状态 | 含义 | 写法 |
|---|---|---|
| 继承 | 旧轮已读，本轮未重开 | 保留旧轮编号、取得层级和当时范围；写「本轮未重开」 |
| 重读 | 本轮重新打开 | 关联本轮访问记录，不冒充首次发现 |
| 新增 | 本轮首次取得 | 进入总索引和线索队列 |
| 修正 | 新证据改变旧表述 | 指出修正哪一条、依据是什么；旧版保留在变更清单 |

合并总卷至少包含：主线、来源总目录（保留 `R001/S05` 这类轮次前缀）、继承/重读/新增/修正清单、覆盖与未解队列。只交本轮新增时，文件直接命名为补充卷，开头写接续哪一轮、哪些旧材料未重开；不要把补充卷写成总卷。同一材料在不同轮次编号不同，保留轮次前缀并列，不重排成两份独立证据。旧轮在线重读失败不删除旧材料，写「本轮未重开，旧轮取得层级为……」，并保留旧轮编号。

## 10. 案头核读模式

用户给定材料、或明确要求不新增检索时使用。不要为了流程完整而编造检索或访问记录。

最低交付：

- **材料清单**：文件、原始来源、作者/发布者、取得层级、是否全文。
- **断言—定位表**：每条结论写来源与页码/行号/时间点；区分本人、他人、机构。
- **冲突与空白**：哪些说法不一致，哪些阶段材料不足。
- **成稿与来源**：正文按人生叙事方法写，来源可回查。
- **范围声明**：写明「本次按用户提供材料核读，未进行独立检索；覆盖范围以材料为限」。

固定材料没有检索记录时，`records.jsonl` 可以只记来源、结论、事件、线索和覆盖；如需覆盖记录，写一条「按提供材料核读」，不要用 `unsearched` 假装查过全网。材料不足时提出具体缺口，不自行联网补查，除非用户允许。

## 11. 案例展示稿（用于宣传时）

用户明确要把案例当宣传材料时，不要只交一篇传记。另交一份短稿：

- **两三个破案现场**：一个互相矛盾的时间或说法；一个怎么找都找不到的死胡同；一个意外找到的原始材料或旧账号。
- **每个现场写四件事**：原来以为什么、找到什么、怎么核验、它改变了哪一处理解。
- **链到完整故事**：末尾给正文与附卷的路径；宣传稿只负责让人看见侦探过程，不替代完整叙事。

正文和附卷仍是主交付；展示稿不新增未经核验的事实，也不把“过程”写成营销话术。
